## 1. Atomic Backup Architecture

All SG Forge SQLite databases run in **Write-Ahead Logging (WAL)** mode. Standard filesystem `cp` commands risk database corruption if a write transaction is in progress. The platform provides an automated atomic backup engine (`scripts/backup-databases.ts`) leveraging SQLite's native `VACUUM INTO` command.

### Invariants of the Backup Engine:
1. **Non-Blocking Operation**: Backups execute concurrently with live read and write traffic with zero query pauses.
2. **Point-in-Time Consistency**: Captures a mathematically consistent snapshot across all tables in a single transaction.
3. **SHA-256 Checksumming**: Every generated tarball is signed with an accompanying `.sha256` manifest.
4. **Storage Pruning**: Automatically retains the last 7 daily snapshots, pruning stale archives to preserve disk space.

## 2. Operational Procedures

### Creating an Immediate Backup
```bash
# Execute full atomic backup across all platform databases
rtk ./run.sh backup
```

The script outputs a timestamped archive inside `data/backups/`:
```text
📦 Backing up auth.db...        ✅ Snapshot created
📦 Backing up portal.db...      ✅ Snapshot created
📦 Backing up dev_dashboard.db...✅ Snapshot created
📦 Backing up code.db...        ✅ Snapshot created
📦 Creating archive: data/backups/backup-2026-09-06_214500.tar.gz
🔒 Writing SHA-256 manifest:   data/backups/backup-2026-09-06_214500.tar.gz.sha256
✨ Backup completed successfully in 420ms.
```

### Restoring from Backup
```bash
# Verify integrity and restore platform databases
rtk ./run.sh restore data/backups/backup-2026-09-06_214500.tar.gz
```

### Storage Permission Hardening
```bash
# Enforce strict POSIX 0700/0600 permissions on data directories
rtk bun scripts/harden-storage.ts
```
