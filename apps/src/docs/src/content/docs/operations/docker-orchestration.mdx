## 1. Dual-Stack Architectural Topography

SG Forge maintains strict, physical separation between the **Development Environment** and the **Production Environment**:

| Architectural Feature | Development Stack (`docker/dev/`) | Production Stack (`docker/prod/`) |
| :--- | :--- | :--- |
| **Compose File** | `docker/dev/docker-compose.yml` | `docker/prod/docker-compose.yml` |
| **Base Image** | `oven/bun:1.3-alpine` (Direct image runner) | Multi-stage builder & runner (`oven/bun:1.3-alpine`) |
| **Code Mirroring** | Host bind mounts (`./src`, `./sdk`, `./ui`) | Immutable, pre-compiled artifact (`/app/dist/server.js`) |
| **Hot Reloading** | Active (`bun --watch`, Linux inotify) | Inactive (Immutable production process) |
| **Compilation** | JIT on-the-fly execution | AOT Bundled, Minified, and Obfuscated |
| **Source Leakage** | Complete local host reflection | **Zero source files leaked** (No `.ts`, `.tsx`, or comments) |
| **Memory Limit** | 128MB per microservice | 256MB per microservice |
| **Port Mapping** | Exposed directly for local debugging | Isolated to Caddy reverse proxy gateway |

## 2. Development Stack & Sub-5ms Hot Reloading

In development, services bypass image rebuilds entirely. All source files, configuration manifests, and libraries are mounted directly from the host filesystem into container memory:

```yaml
# docker/dev/docker-compose.yml snippet
portal:
  image: oven/bun:1.3-alpine
  working_dir: /app
  command: ["bun", "--watch", "apps/src/portal/src/server.ts"]
  volumes:
    - ../../package.json:/app/package.json:ro
    - ../../tsconfig.json:/app/tsconfig.json:ro
    - ../../node_modules:/app/node_modules:ro
    - ../../apps/src/sdk:/app/apps/src/sdk:ro
    - ../../apps/src/types:/app/apps/src/types:ro
    - ../../apps/src/ui:/app/apps/src/ui:ro
    - ../../apps/src/portal:/app/apps/src/portal:rw
    - ag_bun_cache:/root/.bun/install/cache
```

### Invariants of the Dev Pipeline:
1. **Direct Inotify Watch**: The container executes `bun --watch`. Edits on the host filesystem trigger instant delta re-evaluations in sub-5ms without full process respawn.
2. **Read-Only Dependencies**: Monorepo manifests and `node_modules` are mounted `:ro` to prevent accidental host mutation from inside containers.
3. **Dedicated Named DB Persistence**: Local databases write to named volumes (`ag_dev_db_*`), ensuring data persists across container restarts.

## 3. Production Multi-Stage Compilation & Obfuscation

Production deployments enforce a **Zero Source Code Leakage** security policy. Containers do not contain TypeScript source code, package manifests, or node_modules trees.

### Two-Stage Multi-Stage Build Pattern:

```dockerfile
# Stage 1: Build, Compile, Minify & Obfuscate
FROM oven/bun:1.3-alpine AS builder
WORKDIR /build

COPY package.json bun.lock* tsconfig.json ./
RUN if [ -f bun.lock ]; then bun install --frozen-lockfile 2>/dev/null; fi

COPY apps/src/sdk/ apps/src/sdk/
COPY apps/src/types/ apps/src/types/
COPY apps/src/ui/ apps/src/ui/
COPY apps/src/portal/ apps/src/portal/

# AOT bundle & minify into /build/dist (strips comments, mangles identifiers, dead-code elimination)
RUN bun build apps/src/portal/src/server.ts --target=bun --minify --sourcemap=none --outdir /build/dist

# Stage 2: Minimal Hardened Runtime Runner (Zero Source Leak)
FROM oven/bun:1.3-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production

COPY --from=builder /build/dist/server.js /app/dist/server.js
COPY public/ public/

RUN mkdir -p /app/data /app/apps/data /app/apps/src/portal/logs /app/dist && chown -R bun:bun /app
USER bun

EXPOSE 3001
HEALTHCHECK --interval=10s --timeout=3s --start-period=5s --retries=3 \
  CMD wget --no-verbose --tries=1 --spider http://localhost:3001/health || exit 1

CMD ["bun", "dist/server.js"]
```

### Protection Capabilities:
* **Tree-Shaking & Dead-Code Elimination**: Unreferenced functions and modules are purged at build time, shrinking multi-megabyte source trees into compact bundles (<400KB).
* **Identifier Mangling & Minification**: Function names, internal variables, and logic branches are compressed into single-character tokens.
* **Hermetic Source Isolation**: Stage 2 contains only the single obfuscated JavaScript bundle. Proprietary `.ts` algorithms are completely absent from the final shipping image.
* **Non-Root Execution**: Runs under the unprivileged `bun` user (UID 1000) with write permissions restricted to isolated `/app/data` and `/app/logs`.

## 4. Operational CLI Commands via `run.sh`

All Docker operations are driven through the portable `./run.sh docker` wrapper:

```bash
# Start the Development stack with live hot-reload
rtk ./run.sh docker up

# Start specifically a single service or Forge App
rtk ./run.sh docker up code

# Start the Production-hardened container stack
rtk ./run.sh docker prod

# Build all production images with multi-stage compilation
rtk ./run.sh docker build

# Inspect live container health, memory consumption, and status
rtk ./run.sh docker status

# Tail real-time structured logs across all running containers
rtk ./run.sh docker logs

# Gracefully stop all active containers
rtk ./run.sh docker down
```
