## 1. Architectural Topology Overview

The SG Forge platform separates edge routing from internal business execution. The entire platform ingress is dynamically generated from environment variables via `@forge/sdk/registry` and rendered into a unified Caddy reverse proxy configuration.

## 2. Ingress & Routing Specifications

### Gateway Boundaries
* **Perimeter Ingress**: Caddy listens on port `80` (HTTP with automated redirect) and port `443` (HTTPS with modern TLS 1.3 ciphers).
* **Single Source of Truth**: Microservice ports and paths are strictly derived from `@forge/sdk/registry`. Zero hardcoded proxy tables or static ports.
* **RFC 7807 Problem Details**: When an upstream microservice fails or returns an error, the Gateway wraps the response in an RFC 7807 standard JSON structure including an immutable `traceId`.

### Dynamic Path Allocations
| Public Path | Internal Service | Network Zone | Description |
| :--- | :--- | :--- | :--- |
| `/` | `portal` (Port 3001) | `core-airgap-net` | Single Page Application portal shell & navigation |
| `/auth/*` | `auth` (Port 3004) | `core-airgap-net` | Zero-trust authentication engine & session manager |
| `/dev-dashboard/*` | `dev-dashboard` (Port 3002) | `core-airgap-net` | Real-time system monitoring & health telemetry |
| `/apps/code/*` | `forge-apps/code` (Port 8088) | `forge-apps-net` | Autonomous code editor microservice |
| `/docs/*` | `docs-site` (Port 4321) | Edge documentation | Searchable living architecture documentation |

## 3. Network Separation & Air-Gap Boundary

All core platform containers communicate over the isolated `core-airgap-net` Docker network configured with `internal: true`. This guarantees that even if a container process is compromised, it cannot make outbound DNS requests or open outbound socket connections to the internet.
