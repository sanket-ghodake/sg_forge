## 1. The Two-Mode Strix Security Model

SG Forge implements the **Strix Security Standard** (`strix-code-audit` and `strix-live-pentest`) to verify security invariants without external API keys:

### Mode 1: Static AST Code Review (`strix-code-audit` / `audit code`)
- **Trigger**: Run whenever routes, auth handlers, or database queries are modified.
- **Invariants Audited**:
  - **Tenant Scoping**: All database queries must include explicit `eq(table.orgId, session.orgId)` filters.
  - **Secret Leaks**: Scans for hardcoded tokens, API keys, or unredacted passwords.
  - **RFC 7807 Error Boundaries**: Ensures endpoints do not return raw SQL exceptions or internal stack traces.
  - **Cookie Security**: Verifies `HttpOnly`, `SameSite=Lax`, and `Secure` attributes on session cookies.

### Mode 2: Dynamic Live Endpoint Pentest (`strix-live-pentest` / `test live dev`)
- **Trigger**: Run whenever local dev or staging servers are up.
- **Invariants Audited**:
  - Probes endpoints using non-destructive `rtk curl -sI` calls.
  - Verifies presence of security headers: `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, and strict offline Content-Security-Policy.
  - Verifies that unauthorized requests cleanly redirect or return `401 Unauthorized` without leaking session identifiers.

## 2. Automated Logging & Ledger Integrity

Every security audit generates a timestamped report in `logs/security/` (e.g. `AUDIT_YYYYMMDD_HHMM_pre-commit.md`) and appends an immutable JSON record to `logs/security/audit.jsonl`.
