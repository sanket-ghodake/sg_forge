## 3. Threat Vector Analysis & Implemented Defenses

### Threat 1: Token Forgery & Signature Tampering
* **Vector**: Submodule SDKs previously parsed JWT claims via `Buffer.from(parts[1], 'base64url')` without cryptographic signature verification.
* **Mitigation**: Implemented `verifySessionToken` using `node:crypto` Ed25519 public key verification. Any modified claim or forged signature is rejected with RFC 7807 401 Unauthorized or HTTP 302 login redirect.

### Threat 2: Cross-Site State Modification (CSRF)
* **Vector**: Malicious external websites triggering state-changing requests using ambient browser cookies.
* **Mitigation**: Mounted `validateMutatingRequest` across all mutating endpoints (`/tokens`, `/members`, `/apps/requests`). Cross-site requests (`Sec-Fetch-Site: cross-site`) are rejected with HTTP 403 Forbidden.

### Threat 3: Directory PII Harvesting (BOPA)
* **Vector**: Unprivileged callers querying `/api/v1/portal/members` to harvest personal emails and compensation data.
* **Mitigation**: Implemented `sanitizeEmployeeDirectory`. Standard callers receive masked emails (e.g. `d*****e@forge.internal`) with confidential fields removed; administrative roles receive unmasked records.

### Threat 4: Cloud Metadata SSRF
* **Vector**: Outbound webhook or sync calls redirected to cloud hypervisor metadata services.
* **Mitigation**: Implemented `isSafeEgressUrl` blocking `169.254.169.254` and `metadata.google.internal`.
