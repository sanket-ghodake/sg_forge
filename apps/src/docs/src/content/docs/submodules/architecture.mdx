## 1. Submodule Governance & Isolation Model

Forge Apps reside in `forge-apps/*` as autonomous Git submodules. They possess complete independence from core platform internal libraries.

## 2. Invariants & Autonomous Rules

### Invariant 1: Zero Imports from Core (`apps/src/*`)
* Forge submodules MUST NEVER import code from `apps/src/*`.
* Shared platform functionality is consumed exclusively through published, versioned packages (`@forge/sdk`, `@forge/ui`, `@forge/types`).

### Invariant 2: Independent Container Lifecycle
* Each Forge App maintains its own standalone `Dockerfile` and `.dockerignore`.
* Micro-apps operate on `forge-apps-net` with their own environment variables, local port mappings, and health checks.

### Invariant 3: Independent AI Agent Governance
* Each submodule maintains its own local `AGENTS.md` and `GEMINI.md` with localized instructions and domain invariants.
* Changes to submodule applications do not invalidate or require rebuilding core platform containers.

## 3. Submodule Environment & Auth Architecture

### Asymmetric Token Trust & Ingress Boundaries
Central authentication (`apps/src/auth`) signs session tokens. Forge micro-apps sit behind Caddy on `forge-apps-net`, parsing session claims from cookies without storing symmetric signing secrets (`JWT_SECRET`). This strictly eliminates secret sprawl across submodule repositories.

### Standalone vs Gateway Redirection (`AUTH_SERVICE_URL`)
When running behind Caddy, `AUTH_SERVICE_URL` is empty, defaulting to relative `/auth/login`. When running standalone without the gateway, developers specify `AUTH_SERVICE_URL=http://localhost:3000` to redirect unauthorized users to the host auth service.

### Canonical Submodule Environment Variables
| Variable | Required | Default | Description |
| :--- | :--- | :--- | :--- |
| `PORT` | Yes | `3010` | Micro-app HTTP service port |
| `NODE_ENV` | Yes | `development` | Node runtime environment mode |
| `CONTAINER_PREFIX` | Yes | `forge-app-template` | Docker container prefix name |
| `APP_NAME` | Yes | `app-template` | Microservice identifier |
| `AUTH_SERVICE_URL` | No | `""` | Standalone auth redirect URL (empty behind gateway) |
| `DATA_DIR` | No | `./data` | Local Turso SQLite data path |
| `LOG_DIR` | No | `./logs` | Structured JSON logs directory |
| `SESSION_COOKIE_NAME` | No | `forge_session` | Session cookie identifier |
| `BRAND_NAME` | No | `SG Forge` | Display platform name in Astryx UI |
| `BRAND_DOMAIN` | No | `sgforge.local` | Platform host domain |

## 4. Developer Workflow & Submodule Operations

### Cloning with Submodules
```bash
# Clone repository including all autonomous micro-apps
rtk git clone --recurse-submodules <repo-url>

# Or inside an existing workspace:
rtk git submodule update --init --recursive
```

### Developing Inside a Forge App Submodule
```bash
# Navigate to submodule
cd forge-apps/app-template

# Run local development with instant watch mode
rtk ./run.sh dev

# Execute local isolated 5-tier test suite
rtk ./run.sh test

# Verify submodule pre-commit gates
rtk ./run.sh verify
```

### Standalone Docker Execution
```bash
# Launch submodule in isolation
cd forge-apps/app-template
docker compose up -d --build
```
