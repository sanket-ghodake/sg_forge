## 1. Algorithmic Specification

1. When a Forge App or Portal detects a session expiry (HTTP 401 response or cross-tab logout signal), capture the current URL: `window.location.pathname + window.location.search`.
2. Redirect the browser to `/auth/login?return_url=<encoded-current-url>`.
3. The Auth login view reads `?return_url` from query params on mount; if present, stores it in `sessionStorage` under key `forge_return_url` and uses it as the post-login redirect target.
4. On successful authentication, the login completion handler reads `forge_return_url` from `sessionStorage` (fallback: `/portal`) and navigates the user back to their original destination.
5. After redirection, `forge_return_url` is removed from `sessionStorage` to prevent stale replay on future logins.
6. The `set-password-view.ts` first-time password flow also threads `return_url` through query parameters, maintaining continuity across multi-step onboarding.

## 2. Safety & Verification Invariants

* **`return_url` must be URL-encoded** before appending to the auth redirect to prevent open-redirect injection.
* **`sessionStorage` key `forge_return_url` must be cleared after consumption** (single-use).
* **Fallback must always be `/portal`** — never an empty string or external URL.
* **Auth login view must not redirect back to `/auth/login` itself** (prevents infinite redirect loops).
