## 1. Algorithmic Specification

1. **Organization Profile & Brand Identity**: Manage corporate metadata (`name`, `slug`, `domain`, `timezone`, `contact_email`, `settings`) with multi-tenant isolation.
2. **Dynamic Hierarchy Level Types**: Configurable organizational tiers (`Company`, `Division`, `Department`, `Team`, `Squad`, `Unit`) ordered by hierarchical depth rank.
3. **Tree-Structured Organizational Nodes**: Parent-child relationship graph with materialized paths (`/company/engineering/platform`), circular dependency detection, and depth enforcement.
4. **Deterministic Sequential EID Generation**: Configurable employee identification rules (`prefix`, `padding`, `counter`) supporting non-mutating preview (`/eid/preview`) and atomic transaction allocation (`/eid/next`).
5. **Relational Integrity & Cascade Prevention**: Prohibit deletion of organizational nodes that have active child nodes or assigned employee profiles.

## 2. Safety & Verification Invariants

* **Multi-Tenant Isolation**: All operations strictly bounded by `organization_id` derived from session credentials.
* **Anti-Circular Tree Validation**: Enforce that no node can be its own ancestor or descendant.
* **Zero Dummy Data**: All tiers, nodes, and EID sequences are persisted in Turso `auth_organizations`, `auth_org_node_types`, and `auth_org_nodes`.
* **Zero Host Alterations**: CLI and dashboard execution strictly operates through portable Bun wrappers and Astryx tokens.
