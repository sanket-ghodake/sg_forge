## 1. Algorithmic Specification

1. **Dynamic Catalog Segmentation**: Partition applications into active (directly launchable) and marketplace (restricted / requestable) based on role, department ownership, and approved policy bindings.
2. **Access Request Submission**: Employee submits a justification reason and optional project notes, creating a `PENDING` request in `portal_app_access_requests`.
3. **Pending Inbox Routing**: Department managers and organization administrators review incoming pending requests with full requester profile and justification details.
4. **Delegated Decision & Binding**: Upon approval, update request to `APPROVED`, establish an IAM app-level policy binding via `@forge/sdk/directory-client.ts`, and deliver real-time in-app notification.
5. **Anti-Self-Approval Enforcement**: Strictly block administrators and managers from approving their own access requests (`req.user_id === adminUserId`).

## 2. Safety & Verification Invariants

* **IDOR Protection**: Access request cancellation strictly validates `user_id` ownership (`res.changes > 0`).
* **Zero Zombie Access**: Dynamic bindings link directly to central IAM policy tables for instant revocation upon employee offboarding.
* **Smart Collision Detection**: Modals and dropdown selectors enforce viewport containment to guarantee 100% visibility.
