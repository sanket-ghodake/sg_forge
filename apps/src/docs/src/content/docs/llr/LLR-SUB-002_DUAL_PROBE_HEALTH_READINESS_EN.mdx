## 1. Algorithmic Specification

1. Handle GET /health: verify process event loop is active and return HTTP 200 `{ status: 'healthy' }`
2. Handle GET /ready: probe database connection and essential external dependencies
3. If all dependencies respond in &lt; 500ms, return HTTP 200 `{ status: 'ready', checks: [...] }`
4. If any dependency fails, return HTTP 503 Service Unavailable with failing component details

## 2. Safety & Verification Invariants

* **Liveness probe (/health) must respond in &lt; 50ms with zero deep database queries**
* **Readiness probe (/ready) must reflect actual capability to serve user traffic**
