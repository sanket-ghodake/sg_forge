## 1. Algorithmic Specification

1. Every app launch anchor rendered by the Portal (pinned favorites, active app grid, marketplace cards, approved app request cards, app detail modal) must carry the attributes `target="_blank" rel="noopener noreferrer"`.
2. Dynamic app cards rendered client-side via `ui-apps-scripts.ts`, `ui-apps-requests-scripts.ts`, and `ui-renderer-apps.ts` must set these attributes when constructing the HTML string for each launch link.
3. Command palette search result items that open an app must use `window.open(ingressPath, '_blank', 'noopener,noreferrer')` instead of `window.location.href` assignment.
4. The app detail modal "Open Application" anchor (`#app-details-action-btn`) must have `target="_blank" rel="noopener noreferrer"` applied both in the static HTML template and in the dynamic `setAttribute` call when the modal is populated with app data.
5. App ingress paths used as `href` values must be escaped through `escapeHtml()` before injection into HTML strings to prevent XSS.

## 2. Safety & Verification Invariants

* **`rel="noopener noreferrer"` is mandatory** on all `target="_blank"` anchors — prevents the opened tab from accessing the Portal window via `window.opener`, and suppresses the `Referer` header for cross-origin navigations.
* **`window.open` calls must pass `'noopener,noreferrer'` as the third argument** for programmatic launches (command palette) — same security guarantees without an anchor element.
* **Portal navigation state is fully preserved** — since Forge Apps open in a new tab, the Portal SPA view state, scroll position, and active section remain intact in the original tab.
* **Ingress path must be derived from the app registry** (`app.ingressPath` from `/api/v1/portal/apps`) — never constructed from unvalidated user input.
