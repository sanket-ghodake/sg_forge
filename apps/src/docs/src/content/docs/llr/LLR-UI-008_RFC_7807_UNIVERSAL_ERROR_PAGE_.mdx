## 1. Algorithmic Specification

1. **Exhaustive Status Matrix**: Support all 10 standard HTTP error codes: `400`, `401`, `403`, `404`, `405`, `429`, `500`, `502`, `503`, `504`.
2. **Universal Content Negotiation**: Via `@forge/sdk/route-boundary.ts`:
   - If request header includes `Accept: application/json` or URL starts with `/api/`, return RFC 7807 `application/problem+json`.
   - Otherwise, render Astryx high-aesthetic HTML error screen with `Cache-Control: no-cache, no-store, must-revalidate`.
3. **Zero Raw OS Emojis**: Render all status badges and buttons using 100% crisp Lucide 1.75px stroke vector SVGs (`astryxIcons` in `@forge/ui/icons.ts`).
4. **SRE Traceability & Incident Correlation**: Display interactive 1-click copyable `X-Trace-Id` badge.
5. **Anti-Enumeration Defense**: In protected routes (`/portal/*`), unauthenticated requests to unknown subpaths redirect to `/auth/login?return_url=...`.
6. **Edge Pre-Rendering**: Pre-render all 10 error pages into `proxy/errors/` at startup to protect against upstream service downtime.
7. **SEO Spiders Defense**: Inject `<meta name="robots" content="noindex, nofollow, noarchive">` into every error page.

## 2. Safety & Verification Invariants

* **Universal Dual-Theme Parity**: Error screens must seamlessly support dark and light themes using `--forge-*` CSS variables without contrast regressions.
* **Smart Viewport Containment**: Fluid layout down to 320px mobile viewports with zero horizontal scrolling.
* **Never Leak Sensitive Internals**: Stack traces, SQL statements, and internal server paths are strictly omitted.
