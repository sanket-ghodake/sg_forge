## 1. Algorithmic Specification

### Logout Event Emitter (any tab that triggers logout)
1. When the user clicks "Sign Out" or when a `fetch()` intercept receives an HTTP 401 response:
   - Write `localStorage.setItem('forge_logout_event', String(Date.now()))` to trigger cross-origin storage events.
   - If `BroadcastChannel` is supported, open `new BroadcastChannel('forge_auth_channel')`, post `{ type: 'LOGOUT', timestamp: Date.now() }`, and close the channel.
2. Execute the local tab logout: clear `sessionStorage`, call `POST /api/v1/auth/logout` (fire-and-forget), redirect to `/auth/login?return_url=<current-path>`.

### Logout Event Receiver (all other open tabs — Portal, Forge Apps, Docs)
1. On page load (inside inline head `<script>`), register two listeners if the current path is not `/auth/login`:
   - **`BroadcastChannel` listener**: `authBc.onmessage = (ev) => { if (ev.data.type === 'LOGOUT') onCrossTabLogout(); }` on channel `forge_auth_channel`.
   - **`storage` event listener**: `window.addEventListener('storage', (ev) => { if (ev.key === 'forge_logout_event' && ev.newValue) onCrossTabLogout(); })` as a cross-origin tab fallback (storage events fire in all same-origin tabs _except_ the one that wrote).
2. `onCrossTabLogout()` clears `sessionStorage` and redirects to `/auth/login?return_url=<current-path>` preserving the app state URL (see LLR-AUTH-010).

### Fetch Interceptor (automatic 401 detection in all tabs)
1. Wrap `window.fetch` at app boot time: on any non-login response with `status === 401`, emit both `localStorage` and `BroadcastChannel` logout signals, then call `onCrossTabLogout()`.
2. The fetch wrapper is installed in: Portal head-script, all `@forge/ui` apps, and Forge App submodules.

### Selective Exclusion for Independent & Public Services (2026 LTS)
1. **Unauthenticated / Public Services**: Public documentation (`/docs`), developer API test playgrounds (`/gateway`), and public micro-apps (e.g. `/apps/telemetry`) do not enforce central user sessions and must **exclude** the Central Auth Redirect Bridge to prevent spurious redirect ejection when exploring public endpoints.
2. **Independently Authenticated Services**: Developer Dashboard / Dev Center (`/devcenter`) operates with an independent master-password operator session and must exclude the central user session bridge (`enableAuthRedirectBridge: false`).
3. **Execution Control**: In `getHeadStateScript({ enableAuthRedirectBridge: false })`, section 5 (BroadcastChannel listeners, storage listeners, and 401 interceptors) is omitted entirely. Additionally, the default fetch wrapper excludes paths matching `/devcenter`, `/gateway`, and `/docs`.

## 2. Safety & Verification Invariants

* **`BroadcastChannel` name must be the fixed constant `'forge_auth_channel'`** across all apps for reliable synchronization.
* **`localStorage` key `'forge_logout_event'`** serves as a cross-browser fallback; value must be a millisecond epoch timestamp (prevents duplicate triggers on same-value writes).
* **Receivers must guard against duplicate invocations** — after the first logout redirect is triggered, listeners need not be removed because navigation destroys the page context.
* **The fetch interceptor must not intercept responses from `/auth/login` itself** to prevent infinite redirect chains.
* **Exclusion paths (`/devcenter`, `/gateway`, `/docs`) must never trigger 401 redirects to `/auth/login`**, preventing disruption of operator or public exploration workflows.
* **`BroadcastChannel` instances must be closed after postMessage** to release browser resources.
