## 1. The Four Pillars of Observability

Every microservice across `apps/src/*` and `forge-apps/*` must maintain isolated logging and dual-probe telemetry adhering to the 4 pillars:

1. **Dual-Probe Health Monitoring**:
   - `/health/liveness`: Verifies that the container process and HTTP socket are responsive.
   - `/health/readiness`: Verifies upstream database connections, filesystem access, and dependency availability.
2. **Browser Console Observability**:
   - Frontend console logs stream structured JSON via `initBrowserLogBridge`.
   - Never exposes raw database query errors, passwords, tokens, or unhandled stack traces to browser dev tools.
3. **Container & Docker Output**:
   - Standard stdout/stderr streams single-line structured JSON logs with ISO-8601 timestamps, severity levels, service tags, and immutable `traceId` correlation.
4. **Backend Persistent Logs**:
   - Colocated `logs/` directory per microservice with independent `.gitignore` and `README.md`.

## 2. RFC 7807 Standard Error Boundaries

All API error responses must adhere strictly to the RFC 7807 Problem Details specification via `@forge/sdk/createSafeHandler`:

```json
{
  "type": "https://docs.sgforge.local/errors/unauthorized",
  "title": "Unauthorized Access",
  "status": 401,
  "detail": "Session token has expired due to 30 minutes of inactivity.",
  "instance": "/api/users/profile",
  "traceId": "tr-9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
  "timestamp": "2026-09-06T21:45:00Z"
}
```

## 3. Automated PII & Secret Redaction

Before any log record is written to disk or sent to stdout, `@forge/sdk/redactSensitiveData` recursively scrubs keys matching sensitive patterns:
* `password`, `token`, `secret`, `authorization`, `cookie`, `jwt`, `credit_card`, `ssn`.
* Scrubbed values are replaced with `[REDACTED]`, preventing accidental credential leaks in production audits.
