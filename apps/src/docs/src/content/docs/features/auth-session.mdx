## 1. Authentication & Session Lifecycle Overview

The SG Forge Authentication Engine operates inside the core air-gap zone (`core-airgap-net`). It issues cryptographically signed JWT cookies with strict `HttpOnly`, `SameSite=Lax`, and `Secure` attributes.

## 2. Invariants & Security Specifications

### Invariant 1: Sliding Window & Inactivity Timeout
* Sessions have an active sliding expiration (default 30 minutes of idle inactivity).
* Every authenticated request automatically renews the session timestamp in the session store.
* Once the idle limit is exceeded, subsequent requests return an RFC 7807 `401 Unauthorized` with `urn:sgforge:error:session-expired`.

### Invariant 2: Anti-Replay Token Defense
* Session tokens include unique cryptographic `jti` (JWT ID) identifiers and sequence counters.
* The Auth Engine maintains an in-memory or SQLite-backed token revocation blacklist. If a previously refreshed token is presented again, both the replayed token and the current active session are immediately revoked to protect against man-in-the-middle interception.

### Invariant 3: Zero Credential Exposure
* All authentication cookies are marked `HttpOnly`, preventing client-side JavaScript from accessing session tokens.
* Cross-Site Request Forgery (CSRF) is neutralized through strict origin verification and SameSite cookie policies.
